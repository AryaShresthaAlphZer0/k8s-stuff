emptyDir is a temporary, Pod-scoped volume in Kubernetes — it starts out empty and exists only as long as the Pod it belongs to is running. The moment that Pod is deleted, the data is gone permanently, so it should never be used for anything you actually need to keep (use a PersistentVolumeClaim for that instead). The way it works in YAML is always split into two connected pieces: you define the volume itself under the Pod-level volumes: block (giving it a name and emptyDir: {}), and then you attach it to a specific container using that same name under volumeMounts:, specifying a mountPath — the folder path where it will appear inside that container's filesystem. If a container inside the Pod crashes and restarts, the data survives, since the Pod itself hasn't gone away — but if the whole Pod is deleted or rescheduled to a different node, everything is wiped, since emptyDir is tied to a single node's local storage and isn't shared across nodes. One of its most useful features is that multiple containers within the same Pod can mount the exact same emptyDir volume, which makes it a common choice for sharing files between a main application container and a sidecar (like a log-shipping container). By default, emptyDir is backed by whatever disk the node has, but you can instead set medium: Memory to back it with RAM (tmpfs) for faster access at the cost of using node memory, and you can optionally add a sizeLimit to prevent it from growing unbounded and filling up node storage. It requires no external plugin or CSI driver since it's built directly into Kubernetes core, making it the simplest volume type available. Typical use cases include scratch space for temporary computation, caching, or checkpointing data mid-process — anything where losing the data on Pod deletion is perfectly acceptable. As a side note unrelated to emptyDir itself: if you ever see something like command: ["/bin/sh", "-c", "sleep 3600"] in a busybox container in one of these example manifests, that's just a trick to keep an otherwise idle container alive long enough to kubectl exec into it and manually test the mounted volume — it has nothing to do with how emptyDir functions.
